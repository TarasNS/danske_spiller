# US-004 - Guard all localStorage access in legacy games

Status: DONE (implemented and verified; not committed)

## Summary
Every `localStorage` read/write/remove in `adverbs.html`, `danish-antonyms-game.html` and `dansk-praepositioner.html` is now inside try/catch. On failure the in-memory defaults are kept and the game stays playable. Storage keys, data shapes, scoring and other behaviour are unchanged. No `sessionStorage` is used in any of the three files.

## Files changed (guard lines only)
- `adverbs.html`: `loadProgress` read (~592, `stored` defaults to null); `saveProgress` (~604-610); dark-mode read in DOMContentLoaded (~1105, single guarded read into `darkPref`); dark-mode toggle write (~1116); reset `removeItem` (~1168).
- `danish-antonyms-game.html`: `save()` (853); reset `removeItem` (1459). `loadState` (844) was already in try/catch.
- `dansk-praepositioner.html`: `endSpeed` read+write (1236-1238, best defaults to 0); `renderStats` read (1304); `resetProg` removeItem (1350). `loadProg`/`saveProg` were already guarded.
Diff stat: 3 files, 22 insertions, 15 deletions.

## Remaining risks
- Præpositioner Lynrunde "Rekord" best score cannot persist when storage is blocked (the result screen shows `max(score, 0)`), by design (no in-memory fallback added to keep the diff minimal).
- Test driver uses a generic click strategy; the match/missing/correct/trans/fill modes were verified to start (screen rendered), not answered.

## Newly discovered issues (record only)
- Smoke harness requires `#btn-play`; legacy games need a per-game selector or harness change (US-026 area).
- `endSpeed()` does not set `speedLeft=0`, so a pending `speedTick` timeout can overwrite the result screen if called manually while a wrong answer timeout is pending (only reachable via forced call; real timer path sets 0).
