# US-003 — Tidsmaskinen: sentence-adverb placement

Status: IMPLEMENTED (pending native sign-off; see "Needs native review")

## Summary
23 items in `tidsmaskinen/data.js` (14 pluperfect + 9 preterite_vs_perfect, exactly the listed set) had `___ <adverb> ...` with a two-word key, so the completed sentence read e.g. "Jeg var gået allerede hjem". Two-blank frames are only supported by the `conditional` mode (slots renderer), so `index.html` was NOT changed. Fix: the adverb was moved behind the slot to the end of its clause, so the completed sentence is grammatical with a single slot: "Jeg var gået hjem allerede, da du kom.", "Han havde fået visum allerede, ...", "Holdet har vundet alle kampe hidtil.", "Børnene var gået i seng for længst, ...", "Hun havde solgt huset for længst, ...". The adverb stays in the sentence, so options keep their disambiguating cue (otherwise "gik" would also fit "da du kom"). Item ids, options, keys, accepted_answers, notes and timelines unchanged (SRS keys stable; ids' slugs now differ from the sentence word order, which is harmless).
One item rewritten more: `han-havde-glemt-allerede-at-ringe-da-chefen-spurgte` became "Han ___ opgaven allerede, da chefen spurgte." with context "Han glemte opgaven mandag. Chefen spurgte tirsdag." (an "at ringe" infinitive clause cannot take clause-final allerede).
Mode 3 build step (tiles from the completed sentence, <=12 words) unaffected; the spec's build test passed.

## Remaining risks
Clause-final "allerede"/"hidtil" after an object ("Jeg har spist morgenmad allerede") is grammatical but somewhat emphatic; the neutral position is before the participle, which a one-slot item cannot show. A two-blank/aux-only redesign would lose tense contrast distractors.
